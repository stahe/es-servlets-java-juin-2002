    8.1. Herramientas de desarrollo web

    Aquí indicamos dónde encontrar y cómo instalar las herramientas necesarias para el desarrollo web. Algunas herramientas han visto evolucionar sus versiones, y es posible que las explicaciones que se ofrecen aquí ya no sean aplicables a las versiones más recientes. En ese caso, el lector deberá adaptarlas... En el curso de programación web, utilizaremos principalmente las siguientes herramientas, todas ellas disponibles de forma gratuita:

    • un navegador reciente capaz de mostrar XML. Los ejemplos del curso se han probado con Internet Explorer 6.
    • Un JDK (Java Development Kit) reciente. Los ejemplos de este curso se han probado con el JDK 1.4. Este JDK incluye el complemento de navegador Java 1.4, que permite a los navegadores mostrar applets de Java utilizando el JDK 1.4.
    • Un entorno de desarrollo Java para escribir servlets Java. En este caso, se trata de JBuilder 7.
    • Servidores web: Apache, PWS (Personal Web Server), Tomcat.
      • Se utilizará Apache para desarrollar aplicaciones web en PERL (Practical Extracting and Reporting Language) o PHP (Personal Home Page).
      • Se utilizará PWS para desarrollar aplicaciones web en ASP (Active Server Pages) o PHP
      • Tomcat se utilizará para desarrollar aplicaciones web utilizando servlets Java o JSP (Java Server Pages).
    • Una aplicación de gestión de bases de datos: MySQL
    • EasyPHP: una herramienta que integra el servidor web Apache, el lenguaje PHP y el SGBD MySQL

    8.1.3. EasyPHP

    Esta aplicación es muy práctica porque incluye lo siguiente en un único paquete:

    • el servidor web Apache (1.3.x)
    • el lenguaje PHP (4.x)
    • el SGBD MySQL (3.23.x)
    • una herramienta de administración de MySQL: PhpMyAdmin

    La aplicación de instalación tiene este aspecto:

    La instalación de EasyPHP es sencilla y se crea una estructura de directorios en el sistema de archivos:

    easyphp.exe
    el ejecutable de la aplicación
    apache
    la estructura de directorios del servidor Apache
    mysql
    el directorio de la base de datos MySQL
    phpMyAdmin
    la estructura de directorios de la aplicación phpMyAdmin
    PHP
    la estructura de directorios de PHP
    www
    raíz del árbol de directorios para las páginas web servidas por el servidor Apache de EasyPHP
    cgi-bin
    directorio donde puedes colocar scripts CGI para el servidor Apache

    La principal ventaja de EasyPHP es que la aplicación viene preconfigurada. Por lo tanto, Apache, PHP y MySQL ya están configurados para funcionar juntos. Cuando inicias EasyPHP a través de su acceso directo en el menú Programas, aparece un icono en la esquina inferior derecha de la pantalla.

    Se trata de la letra E con un punto rojo, que debería parpadear si el servidor web Apache y la base de datos MySQL están operativos. Al hacer clic con el botón derecho del ratón sobre él, se accede a las opciones del menú:

    La opción «Administración» te permite configurar los ajustes y realizar pruebas de funcionalidad:

    8.1.3.2. Administración de Apache

    Sin salir de la página de administración de EasyPHP, el enlace «Tus alias» te permite definir alias asociados a un directorio. Esto te permite colocar páginas web fuera del directorio www en el árbol de directorios de EasyPHP.

    Si, en la página anterior, introduces la siguiente información:

    y hace clic en el botón «Validar», se añaden las siguientes líneas al archivo <easyphp>\apache\conf\httpd.conf:

        Alias /st/ "e:/data/serge/web/"

    <Directory "e:/data/serge/web">
        Options FollowSymLinks Indexes
        AllowOverride None
        Order deny,allow
        allow from 127.0.0.1
        deny from all
    </Directory>

    <easyphp> hace referencia al directorio de instalación de EasyPHP. httpd.conf es el archivo de configuración del servidor Apache. Por lo tanto, puede obtener el mismo resultado editando este archivo directamente. Los cambios en el archivo httpd.conf suelen ser aplicados inmediatamente por Apache.     y solicita esta página utilizando el alias st:

    En este ejemplo, el servidor Apache se ha configurado para ejecutarse en el puerto 81. Su puerto predeterminado es el 80. Esto se controla mediante la siguiente línea del archivo httpd.conf que ya hemos visto:

    Si desea ajustar Apache, debe editar manualmente su archivo de configuración httpd.conf, ubicado aquí, en la carpeta <easyphp>\apache\conf:

    A continuación se indican algunos puntos clave a tener en cuenta en este archivo de configuración:

    línea(s)
    función
    ServerRoot "D:/Archivos de programa/Apache Group/Apache"
    especifica la carpeta que contiene la estructura de directorios de Apache
    Puerto 80
    especifica qué puerto utilizará el servidor web. Normalmente, es el 80. Al cambiar esta línea, puedes hacer que el servidor web se ejecute en un puerto diferente
    ServerAdmin root@istia.univ-angers.fr
    la dirección de correo electrónico del administrador del servidor Apache
    ServerName stahe.istia.uang
    el nombre del equipo en el que se ejecuta el servidor Apache
    ServerRoot "E:/Archivos de programa/EasyPHP/apache"
    el directorio de instalación del servidor Apache. Cuando aparecen nombres de archivos relativos en el archivo de configuración, se refieren a este directorio.
    DocumentRoot "E:/Archivos de programa/EasyPHP/www"
    el directorio raíz del árbol de páginas web servidas por el servidor. Aquí, la URL http://machine/rep1/fic1.html corresponderá al archivo E:\Archivos de programa\EasyPHP\www\rep1\fic1.html
    <Directory "E:/Archivos de programa/EasyPHP/www">
    establece las propiedades de la carpeta anterior
    ErrorLog logs/error.log
    carpeta logs, por lo que, en la práctica, <ServerRoot>\logs\error.log: E:\Archivos de programa\EasyPHP\apache\logs\error.log. Este es el archivo que debes consultar si observas que el servidor Apache no funciona.
        ScriptAlias /cgi-bin/ "E:/Archivos de programa/EasyPHP/cgi-bin/"
    E:\Program Files\EasyPHP\cgi-bin será la raíz del árbol de directorios donde puedes colocar scripts CGI. Por lo tanto, la URL http://machine/cgi-bin/rep1/script1.pl será la URL del script CGI E:\Program Files\EasyPHP\cgi-bin\rep1\script1.pl.
    <Directory "E:/Archivos de programa/EasyPHP/cgi-bin/">
    establece las propiedades de la carpeta anterior
    LoadModule php4_module "E:/Archivos de programa/EasyPHP/php/php4apache.dll"
AddModule mod_php4.c
    Líneas para cargar los módulos que permiten a Apache trabajar con PHP4.
        AddType application/x-httpd-php .phtml .pwml .php3 .php4 .php .php2 .inc
    establece las extensiones de archivo que se tratarán como archivos PHP

    8.1.4. PHP

    Ya hemos visto cómo obtener PHP a través de la aplicación EasyPHP. Para obtener PHP directamente, ve al sitio web http://www.php.net.

    PHP no se limita al uso web. Puedes utilizarlo como lenguaje de scripting en Windows. Crea el siguiente script y guárdalo como date.php:

    <?
  // script php affichant l'heure
  $maintenant=date("j/m/y, H:i:s",time());
  echo "Nous sommes le $maintenant";
?>

    8.1.6. VBScript, JavaScript, PerlScript

    Estos son lenguajes de scripting para Windows. Pueden ejecutarse en diversos entornos, tales como

    • Windows Scripting Host para su uso directo en Windows, especialmente para escribir scripts de administración del sistema
    • Internet Explorer. Se utiliza entonces dentro de páginas HTML, a las que añade un nivel de interactividad que no se puede lograr solo con HTML.
    • Internet Information Server (IIS), el servidor web de Microsoft en NT/2000, y su equivalente, Personal Web Server (PWS), en Win9x. En este caso, VBScript se utiliza para la programación web del lado del servidor, una tecnología denominada ASP (Active Server Pages) por Microsoft.

    Descargue el archivo de instalación desde la URL: http://msdn.microsoft.com/scripting y siga los enlaces de Windows Script. Se instalarán los siguientes componentes:

    • el contenedor Windows Scripting Host, que admite varios lenguajes de scripting como VBScript y JavaScript, así como otros como PerlScript, que se incluye con Active Perl.
    • un intérprete de VBScript
    • un intérprete de JavaScript

    Hagamos unas pruebas rápidas. Creemos el siguiente programa VBScript:

    ' a class
class personne
  Dim nom
  Dim age
End class

' creation of a person object
Set p1=new personne
With p1
  .nom="dupont"
  .age=18
End With

' display properties person p1
With p1
  wscript.echo "nom=" & .nom
  wscript.echo "age=" & .age
End With

    Este programa utiliza objetos. Llamémoslo objects.vbs (la extensión .vbs indica que se trata de un archivo VBScript). Ve al directorio donde se encuentra y ejecútalo:

    Un último ejemplo en PerlScript para terminar. Debes tener instalado Active Perl para acceder a PerlScript.

    <job id="PERL1">
  <script language="PerlScript">
      # du Perl classique
    %dico=("maurice"=>"juliette","philippe"=>"marianne");
    @cles= keys %dico;
    for ($i=0;$i<=$#cles;$i++){
        $cle=$cles[$i];
      $valeur=$dico{$cle};
        $WScript->echo ("clé=".$cle.", valeur=".$valeur);
    }
    # du perlscript utilisant les objets Windows Script
    $dico=$WScript->CreateObject("Scripting.Dictionary");
    $dico->add("maurice","juliette");
    $dico->add("philippe","marianne");
    $WScript->echo($dico->item("maurice"));
    $WScript->echo($dico->item("philippe"));    
  </script>
</job>

    Este programa muestra cómo crear y utilizar dos diccionarios: uno al estilo clásico de Perl y otro utilizando el objeto Windows Script Scripting Dictionary. Guardemos este código en el archivo dico.wsf (wsf es la extensión de los archivos de Windows Script). Accedamos a la carpeta del programa y ejecutémoslo:

    E:\data\serge\windowsScripting\perlscript\essais>cscript dico.wsf
Microsoft (R) Windows Script Host Version 5.6
Copyright (C) Microsoft Corporation 1996-2001. Tous droits réservés.

clé=philippe, valeur=marianne
clé=maurice, valeur=juliette
juliette
marianne

    PerlScript puede utilizar objetos del contenedor en el que se ejecuta. En este caso, se trataba de objetos del contenedor de Windows Script. En el contexto de la programación web, los scripts de VBScript, JavaScript y PerlScript pueden ejecutarse tanto en el navegador IE como en un servidor PWS o IIS. Si el script es algo complejo, puede ser conveniente probarlo fuera del contexto web, dentro del contenedor de Windows Script, tal y como se ha visto anteriormente. De esta forma, solo se pueden probar las funciones del script que no utilizan objetos específicos del navegador o del servidor. Incluso con esta restricción, esta opción sigue siendo útil, ya que, por lo general, resulta bastante poco práctico depurar scripts que se ejecutan en servidores web o navegadores.

    8.1.8.3. Enlace PERL-APACHE

    Esto se consigue utilizando una línea del tipo: ScriptAlias /cgi-bin/ "E:/Program Files/EasyPHP/cgi-bin/" en el archivo <apache>\conf\httpd.conf. Su sintaxis es ScriptAlias /cgi-bin/ "<cgi-bin>", donde <cgi-bin> es la carpeta en la que se pueden colocar los scripts CGI. CGI (Common Gateway Interface) es un estándar para la comunicación entre el servidor web y las aplicaciones. Un cliente solicita una página dinámica al servidor web, es decir, una página generada por un programa. Por lo tanto, el servidor web debe indicar a un programa que genere la página. CGI define la interacción entre el servidor y el programa, concretamente cómo se transmite la información entre estas dos entidades.

    Si es necesario, modifique la línea ScriptAlias /cgi-bin/ &quot;&lt;cgi-bin&gt;&quot; y reinicie el servidor Apache. A continuación, realice la siguiente prueba:

    8.1.9. El servidor PWS

    8.1.9.1. Instalación

    El PWS (Personal Web Server) es una versión personal del IIS (Internet Information Server) de Microsoft. El IIS está disponible en equipos con NT y 2000. En equipos con Win9x, PWS suele estar incluido en el paquete de instalación de Internet Explorer. Sin embargo, no se instala de forma predeterminada. Debes realizar una instalación personalizada de IE y solicitar la instalación de PWS. También está disponible en el NT 4.0 Option Pack para Windows 95.

    8.1.9.2. Pruebas iniciales

    El directorio raíz de las páginas web de PWS es unidad:\inetpub\wwwroot, donde unidad es el disco en el que se ha instalado PWS. A partir de ahora daremos por hecho que esta unidad es D. Por lo tanto, la URL http://machine/rep1/page1.html corresponde al archivo d:\inetpub\wwwroot\rep1\page1.html. El servidor PWS interpreta cualquier archivo con la extensión .asp (Active Server Pages) como un script que debe ejecutar para generar una página HTML.

    PWS se ejecuta en el puerto 80 de forma predeterminada. El servidor web Apache también... Por lo tanto, debe detener Apache para trabajar con PWS si tiene ambos servidores. La otra solución es configurar Apache para que se ejecute en un puerto diferente. En el archivo de configuración de Apache httpd.conf, sustituya la línea «Port 80» por «Port 81». Apache se ejecutará ahora en el puerto 81 y podrá utilizarse simultáneamente con PWS. Si PWS está en ejecución y solicita la URL «http://localhost», verá una página similar a la siguiente:

    8.1.10. Tomcat: servlets de Java y JSP (Java Server Pages)

    Tomcat es un servidor web que genera páginas HTML utilizando servlets (programas Java ejecutados por el servidor web) o JSP (Java Server Pages), que combinan código Java con código HTML. Es el equivalente a ASP (Active Server Pages) en el servidor IIS/PWS de Microsoft, donde el código VBScript o JavaScript se combina con código HTML.

    8.1.10.1. Instalación

    Tomcat está disponible en la URL: http://jakarta.apache.org. Descargará un archivo de instalación .exe. Al ejecutar este programa, primero le pedirá que seleccione qué JDK va a utilizar. Esto se debe a que Tomcat requiere un JDK para instalarse y, posteriormente, para compilar y ejecutar servlets Java. Por lo tanto, debe tener instalado un JDK de Java antes de instalar Tomcat. Se recomienda utilizar el JDK más reciente. La instalación creará una estructura de directorios <tomcat>:

    consiste simplemente en extraer este archivo en un directorio. Elige un directorio cuya ruta contenga solo nombres sin espacios (no, por ejemplo, «Archivos de programa»), ya que hay un error en el proceso de instalación de Tomcat. Utiliza, por ejemplo, C:\tomcat o D:\tomcat. Llamemos a este directorio <tomcat>. En su interior, encontrarás una carpeta llamada jakarta-tomcat, que contiene la siguiente estructura de directorios:

    8.1.11. JBuilder

    JBuilder es un entorno de desarrollo de aplicaciones Java. Para crear servlets Java sin interfaces gráficas, este entorno no es estrictamente necesario. Basta con un editor de texto y un JDK. Sin embargo, JBuilder ofrece algunas ventajas con respecto al método anterior:

    • facilidad de depuración: el compilador resalta las líneas erróneas de un programa, y es fácil navegar hasta ellas
    • autocompletado de código: al utilizar un objeto Java, JBuilder muestra una lista de sus propiedades y métodos en línea. Esto resulta muy útil, dado que la mayoría de los objetos Java tienen numerosas propiedades y métodos que son difíciles de recordar.

    JBuilder se puede encontrar en http://www.borland.com/jbuilder. Para obtener el software, hay que rellenar un formulario. Se envía una clave de activación por correo electrónico. Para instalar JBuilder 7, por ejemplo, se siguieron los siguientes pasos:

    • Se descargaron tres archivos ZIP: uno para la aplicación, otro para la documentación y otro para los ejemplos. Cada uno de estos archivos ZIP tiene un enlace independiente en el sitio web de JBuilder.
    • Primero se instaló la aplicación, luego la documentación y, por último, los ejemplos
    • Al iniciar la aplicación por primera vez, se solicita una clave de activación: es la que se le envió por correo electrónico. En la versión 7, esta clave es en realidad un archivo de texto completo que se puede colocar, por ejemplo, en la carpeta de instalación de JB7. Cuando se solicita la clave, debe especificar el archivo en cuestión. Una vez hecho esto, no se volverá a solicitar la clave.

    Hay algunas configuraciones útiles que debes establecer si quieres utilizar JBuilder para crear servlets Java. La denominada versión «Personal» de JBuilder es una versión reducida que no incluye todas las clases necesarias para el desarrollo web en Java.
